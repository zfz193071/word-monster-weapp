# 听词选怪与开战门控（#9）

依据已确认 A2/A4/C7；纯门控为 `fortress/listening.ts`，原生界面为 `components/fortress-choice/`。

## 接入协议

每个听词阶段创建一个控制器，传入不可变 SessionPlan、waveIndex、generation。首次 `start()` 播放题目词音；自然结束且两个实际怪物头像都加载成功后才允许选择。界面只显示序号无障碍标签，不显示中英文答案。

- `choose(token, wordId)` 验证当前交互代次。错误记录 Attempt、温和提示并重播，不改基地血量或怪物耐久。第二次错后持续高亮正确头像，后续 Attempt 的 hintUsed 为 true。重播/重试不打乱选项。
- 正确立即锁定本控制器并停止音频，仅发出一次 `onStartCombat({context, attempts})`；不会产生击败事实。编排器验证完整上下文后创建目标词战斗。
- replayCount 沿用既有口径：用户重播与答错后的自动重播计数；音频故障重试、后台恢复重播不计数。attemptIndex 从 1 递增，故障不计答错。
- 头像事件使用独立 imageToken，重试重新挂载图片并失效旧加载回调。交互 token 包含 sessionId/waveId/generation/本地 revision；播放、暂停及恢复都会使旧点击失效。
- 题目词音错误只能重试，无跳过开战。头像失败也必须重试成功。暂停停止声音，恢复时重播未结束词音；已听完无需重播，但旧点击仍失效。
- 换波、退出、技能/终局阶段销毁控制器；宿主每次新阶段须更新 generation，不用相同上下文重新创建控制器。组件另有实例 epoch 防护，隔离旧资源回调。

## 自动验证

`tests/listening.test.ts` 覆盖音频/头像双门控、正确开战幂等、两次错误与提示、尝试与重播计数、超时/平台错误、图片重试、后台恢复及旧代次/跨局/销毁回调隔离。效果依赖真实音频适配器，以可控制的原生音频替身触发自然结束与故障。

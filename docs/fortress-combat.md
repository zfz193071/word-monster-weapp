# #20 战斗模拟接入说明

状态：纯模拟与帧适配层已实现；未接入现有 V1 battle 页面，也不代表美术、退场词音、技能面板或真机验收完成。业务参数来自用户已确认的 [A1—C8](mvp-v2-rules-proposal.md)。

## API 与责任

- `createCombat(options)`：验证 SessionPlan、波次、基地剩余血量、局内技能及事件身份，创建当前波和立即首发的弹体。调用方必须先完成听词选怪门控；构造函数不会把“选对”当作击败。
- `stepCombat(state, input)`：推进一个 10ms 固定逻辑步，返回新只读快照和该步事件。传入上一步返回的 state；不重复提交旧快照的事件。该层没有微信 API、音频、随机调用或全局时钟。
- `getWeaponParameters(levels)`：把三个技能的绝对等级转为弹数、间隔、宽度。技能只在波间选择，将完整等级传给下一波 `createCombat`；同一波不叠加面板点击。offer 消费与去重属于 #11。
- `CombatRunner.frame(nowMs, input)`：Canvas 的帧时间戳适配器，每帧最多补 10 个逻辑步；其余完整步的积压丢弃并在 `droppedMs` 中报告。相同时间戳不重复推进。10ms 步长与 100ms 补帧上限是实现策略，未更改玩法数值。
- `pause()` 冻结快照并清空待补时间；`resume(nowMs, generation)` 使用新的低频代次恢复，不补后台时间；`dispose()` 释放快照，后续 frame 不产生事件。调用方 #13 仍须取消真实帧请求、释放触摸和音频。

## 坐标与资源边界

主角/怪物位置、弹体宽高与碰撞矩形均使用 360×560 逻辑坐标。怪物 `hitbox` 是相对怪物位置的偏移矩形，不是屏幕坐标。

构造参数 `monsterHitbox` **必填，没有生产默认值**。#21 应按实际素材 `MonsterVisual` 的原图 hitbox、anchor 和绘制缩放计算：`x=(hitbox.x-anchor.x)*scale`、`y=(hitbox.y-anchor.y)*scale`、宽高乘同一 scale；渲染与碰撞必须共用变换。#4 尚未完成，测试中的 64×64 矩形和薄目标均明确是测试数据，不是已审校怪物形象。

主角 x 被限制在 24—336，y 始终为 510；已有弹体保持发射时的 x，之后移动只改变新发弹体的弹道。子弹离开上边界后释放；本规则的保守弹体上限为 28，按最大弹数、最小间隔、飞行速度和在场寿命推导。当前始终只有一只本波怪物。

## 伤害、计时与终态

1. 怪物移动/抵达，更新攻击冷却；抵达时不足一个逻辑步的剩余时间才可计入首次 2 秒等待。
2. 子弹真实移动，以相对运动的扫掠矩形求接触时刻；薄目标不因两帧间穿越而漏判。按接触时刻和稳定索引处理命中，普通弹体消费一次。
3. 怪物 hp 归零只发一次 `monsterDefeated`。同一步只允许仍存活且冷却到期的怪物攻击，攻击 ID 包含实体与周期号。
4. 基地 hp 归零发一次 `baseDestroyed`；全怪击败时状态为 `cleared`，**不是整局胜利**。两种状态均清空弹体，后续 step 不再推进。
5. `cleared` 保留击败怪物的最后位置，供 #22 残影/词音流程使用；残影完成后 #10 才进入技能或整局通关。动画回调不能扣怪物耐久。

基地血量由上波结果明确传入，禁止零血开始新波，不自动修复。高频 tick 不改变 context.generation；暂停恢复使 generation 递增，旧异步事件的拦截仍由会话编排负责。

## 验证结果

`npm run check` 通过，`npm test` 73/73 通过（本单新增 14 项）：

- 启动不自动击败、移动/射击/实际命中、同一步命中与基地攻击优先级。
- 12 秒抵达、抵达后完整 2 秒首次攻击、连续五次扣血后的唯一失败事件。
- 单弹/多弹一次消费与击败去重、薄目标/高速相对运动/擦边与横向错开。
- 技能改变实际弹数/周期/碰撞宽度、跨波不回血、新局清空状态。
- 固定种子和逐步输入重放、不可变快照、弹体回收/上限、错误输入。
- 不同帧间隔、重复时间戳、有限补帧、暂停 30 秒后不补攻击、销毁后不再产生事件。

这些是逻辑与适配器测试。实际触摸/DPR/帧时间/动画与声音需要 #21/#22/#13/#15 分别验证，素材缺口和人工听审仍由 #4 完成。

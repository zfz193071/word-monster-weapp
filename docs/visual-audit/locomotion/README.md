# #99 怪物移动姿态：首轮接入

## 最新用户澄清：四足动物必须呈现自然奔跑体态

用户再次强调：“动物若四肢着地，是自然奔跑的姿势。”要求的是四足动物完整、自然的奔跑体态：躯干保持对应动物的四足姿态，前后肢有协调的伸展、落地、蹬地及适合该动物的身体运动，不能沿用近似直立/人形的身体，仅添加四条摆动的腿或上下挪脚。

此前首轮代码只调整肢体循环，未解决四足躯干及完整奔跑姿态，未满足此要求；已有回放仅作失败方案/整改前证据，不作为自然奔跑验收通过。后续按各动物形态制作和接入完整奔跑表现，不将所有四足动物机械套成同一种对角步态。僵尸和双足动物仍要求正常走路；实际移动速度及战斗数值保持不变。


按最新用户要求区分僵尸双足行走、四足动物奔跑与双足动物行走。复核现行 #85/#88/#92/#98 与 11 月 9～10 日需求，没有发现需关闭的明确冲突工单。

正式映射见 `miniprogram/fortress/monster-gait.ts`：

- 四足：熊、猫、牛、狗、象、马、狮子、熊猫、兔、羊、虎，按当前四足战斗形态使用对角肢体配合的跑步循环。
- 双足动物：鸡、鸭，增加交替支撑、抬脚回摆与脚掌落地。
- 僵尸：现有程序腿部增加髋/膝/脚连接；精细苹果图沿用腿部裁片，以支撑伸展、回摆压缩表现步态。没有新增独立的手臂或多帧美术资源。
- 蜜蜂、鸟、鱼沿用现有飞行/游动，不强行改为着地行走。

步态相位来自实际纵向移动距离，不使用独立计时器。实际位置冻结时保留原姿势，恢复继续；减速、倍速随正式战斗位移变化。到达堡垒后停止步态循环，沿用既有攻击前探；目前停在到达时的脚部姿势，尚未增加独立收脚站稳过渡。没有修改战斗引擎、移动速度、碰撞、伤害、数量或奖励。

[动态审查](review.html)包含手机390×620、平板1024×580，均DPR2、30fps的6段12秒自然首轮开场回放：苹果、猫、鸡鸭/猫马混编。通过正式出怪工厂和Canvas帧循环输出，没有注入怪物位置、血量或伤害。`report.json`记录每秒位置与状态；`phone-gait-frames.png`为手机混编视频第7秒起每秒4帧的局部连续帧，供看步态，不替代完整画面。

复现：`WM_CANVAS_MODULE=/tmp/wm-render-tools/node_modules/@napi-rs/canvas node --import tsx scripts/render-monster-gait.mts`。

验证：`npm run check`通过，41项步态/Canvas测试及12项倍速等价/兵种回归通过；ffprobe核对6段视频均360帧、30fps、DPR2。已目视检查手机连续帧与平板混编关键帧。源码预算主包1749.8KiB、图片包2038.0KiB，无新增运行图片。历史V2十项资源待审提示仍存在。

验收边界：这是步态首轮代码接入及离屏证据，不是完整关卡、微信模拟器、真机或用户视觉验收。动物仍是现有程序绘制形象，精细苹果腿部仍为单图裁片变形；精细独立动作素材、手臂协调、停止收脚过渡及全部动物逐个观感验收仍需继续。#99保持开放，不将本轮标为“自然姿态全部完成”。

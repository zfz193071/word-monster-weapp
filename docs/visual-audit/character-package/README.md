# #86 角色资源分包迁移

将一级精细主角与普通苹果僵尸两张运行图原样迁入 `miniprogram/character-assets`，为后续动物与僵尸美术留出独立空间。未更换画质、动作、数值或碰撞规则。

## 加载与容量

- `app.json` 注册普通分包，静态 `require.async` 导入 ready 模块。
- 按实际 SceneArt 的主角和精细怪物路径决定是否加载，包含历史词条混编；高级主角且不含苹果时不下载角色包。
- 首次进场先等待所需分包，再解码 Canvas 图片；连续闯关先等待下一关分包再预加载图片。退出或重建后旧请求不继续解码/开战。
- 并发共享、成功缓存；失败或15秒超时可重试，旧回调不污染新请求。
- 源码预算：图片包 2038.0 → 1864.1 KiB；角色包 174.0 KiB；主包 1761.9 KiB。各包均低于项目2048 KiB预算。
- 运行PNG合计178073字节，SHA256和透明度保持不变。两图RGBA估算895188字节，不含纹理副本；迁移不减少需要两图时的解码内存。

## 验证与边界

资源SHA256、无重复副本与两端重绘截图比对记录见 [migration.json](migration.json)。使用正式Canvas生成的手机和平板猫场景PNG与迁移前样片逐字节相同。新增角色分包的按需/混编加载、重试、缓存、超时迟到回调测试，复用现有退出与首帧门控回归。

本轮未运行微信开发者工具编译或真机测试，实际下载耗时、峰值内存和编译包体仍待验证。尝试访问微信官方分包文档失败，未据第三方页面宣称已核实最新平台限制。不是#86全部完成或动物动作、形象视觉验收通过。
